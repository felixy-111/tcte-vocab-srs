# 統測單字（SRS 手機 App）

學生在家每天約 20 分鐘的單字複習。單檔 `index.html`，沒有框架、沒有建置步驟。

## 資料從哪來
題庫是唯一真相來源，改了題庫就重跑：

```bash
cd ~/projects/felix_agent/tutoring/統測字彙測驗
python3 工具/build_srs.py         # 題庫＋卡片增補＋圖 → srs/data/cards.json、srs/img/
python3 工具/build_srs_audio.py   # 補產音檔到 srs/audio/（已存在的跳過）
```

- 新進度日程（哪天上哪一批、哪天考）寫在 `工具/build_srs.py` 的 `SCHEDULE`
- 已學範圍（進總複習）是 `LEARNED`
- 統測日期是 `index.html` 的 `EXAM_DATE`（簡章公告後改）

## ⚠️ 改任何東西都要改 sw.js 的 CACHE 版本號
`sw.js` 是「快取優先」：手機會先用存好的舊檔。
**只要 `index.html`、`data/`、`audio/`、`img/` 有任何變動，就把 `sw.js` 裡的 `CACHE = "tsvt-srs-vN"` 的 N +1**，
不然學生手機會一直停在舊版。PWA 更新要在 GitHub Pages 上實測才算數（本機 http 不會註冊 service worker）。

## 測試用網址參數
- `?selftest=1`：模擬 30 天排程（假時鐘），檢查本批每天出現、每日份量、舊字首檢、拼錯隔 3 張/60 秒再出、只評第一次、過關閘門、加強卡、20 秒分界、FSRS 基本性質，以及雲端同步（合併規則、假伺服器模擬多台裝置分岔再收斂、空裝置不覆蓋、老師儀表板不吃 HTML）。`&days=75` 可拉長
- `?today=2026-10-07`：假裝今天是某天（台北時間晚上 7 點），測上課日／考前一天。雲端模式下這個模式**另存一份、不同步**（假日期不會混進學生真的進度）
- `?teacher=1`：老師端（雲端模式才有）
- 進度存在 `localStorage` 的 `tsvt-srs-v2`；雲端同步的紀錄在 `tsvt-srs-sync`

## 雲端同步＋老師端（Supabase）
跟「統測字彙練習 app」共用同一個 Supabase 專案。`index.html` 的 `CONFIG` 留空＝只存這台裝置（跟以前一樣）。

開啟步驟（一次性）：
1. Supabase → SQL Editor → 貼上 `supabase/001_srs.sql` → Run。最後會列出「有老師權限的帳號」，確認只有自己
2. 同一處貼上 `supabase/002_verify.sql` → Run。看到紅字開頭是「驗證全部通過」＝成功（紅字是刻意的，用來把測試資料復原）
3. 把 `app/index.html` 的 `CONFIG` 兩個值（URL、anon key）貼進本 App 的 `CONFIG`；`sw.js` 版本號 +1；部署
4. 打開 `…/srs/?teacher=1` → 用統測字彙 app 的老師帳密登入 → 新增學生 → 複製連結私訊給學生

- 學生：點連結開一次就記住。iPhone「加入主畫面」後的 App 跟 Safari 是分開的儲存空間 → 第一次從主畫面打開時，點畫面最下面「點這裡連結雲端」，貼上同一個連結
- 只上傳改過的部分（作答後 5 秒、最晚 30 秒）；另一台先寫了會自動合併後重送；新裝置沒下載過雲端之前絕不上傳；每次開網頁先整包下載合併，上傳只送比雲端新的（雲端不會倒退）
- 連結外流：老師端「重新產生連結」，舊的立刻失效、進度不受影響
- 權限設計、威脅模型、救援方法：`supabase/SECURITY.md`

## 排程規則（摘要）
- 每個字只有一張長期卡：中→英拼寫（FSRS-5 預設參數、目標記憶率 0.9、最大間隔 45 天）
- 英→中「認得」只在新字輸入當天練，不排長期
- 判分全自動：拼錯或按「不會（看答案）」＝重來；20 秒內拼對＝良好；超過 20 秒＝困難（`GOOD_MS`）
- 長期排程只吃「當天第一次作答」；當天之後的重拼只管今天過不過關
- 拼錯的卡隔 ≥3 張且 ≥60 秒再出（只剩它就直接出）；同一字當天錯滿 4 次 → 加強卡（例句＋照抄 3 次）
- 新字當天學習步驟 1 分 → 10 分（良好往下走、困難重複這步、重來回第一步）
- 每天一開始就固定今天的清單（約 20 分鐘）：本批 → 昨天沒過的 → 舊字首次檢測 20 項（錯題優先）→ 到期複習；放不下的留到明天
- 過關＝清單裡每張在最後一次拼錯之後都拼對過，才顯示「今天的複習完成」；中途關掉再開會接著做
- 考前一天：本批 18 題排最前面當模擬考；考前 6 週起每張卡至少到期一次（`EXAM_DATE`）
- 每天的紀錄在 state 的 `days[日期]`：`set`（清單）、`passed`、`ms`（作答分鐘）、`graded`（第一次評分）、`fails`（各字錯幾次）、`mockFirst`（模擬考第一次對錯）——老師端／雲端同步讀這裡
